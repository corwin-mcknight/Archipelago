# Working on Archipelago

Read [CONTRIBUTING.md](CONTRIBUTING.md) for the development workflow and validation expectations.

**GitHub owns planning and organization.** Use [issues](https://github.com/corwin-mcknight/Archipelago/issues), [milestones](https://github.com/corwin-mcknight/Archipelago/milestones), and the [project](https://github.com/users/corwin-mcknight/projects/1) for implementation plans, task breakdowns, blockers, progress, and follow-up work. Keep each change tied to a scoped issue and PR. Preserve the distinction between source review findings and reproduced failures. Do not create repository backlog files, milestone checklists, or implementation-plan directories.

Keep durable technical contracts and current-system explanations in `docs/Design` and `docs/Kernel`, updating them with the code. Preserve the [accepted constraints](docs/Design/Accepted%20Constraints.md). Use [BUILDING.md](BUILDING.md) for commands and [Development](docs/Development.md) for code conventions.

Write coherent paragraphs, highlight important short phrases in **bold**, and use compact lists only when useful. Do not use Markdown horizontal separators.
